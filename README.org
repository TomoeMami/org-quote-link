#+title: org-quote-link
#+author: Riko
#+options: toc:nil num:nil

[[file:README-en.org][English]] · 中文

把光标放在一个 Org 链接上，执行 =org-quote-link= 命令，链接所在行就会变成一个
“引用块”：链接放进 header，链接指向的内容以转义后的快照形式放进
=#+begin_quote= 与 =#+end_quote= 之间。

#+begin_src org
  [[file:~/notes/emacs.org::*Org 链接]]
#+end_src

执行之后：

#+begin_src org
  #+HEADER: :transclude [[file:~/notes/emacs.org::*Org 链接]]
  ,#+begin_quote
  ,* Org 链接
  Org 链接的正文……

  ,** 子标题
  子标题的正文。
  ,#+end_quote
#+end_src

* 安装

要求 Emacs 27.1 与 Org 9.3。本包只依赖 Org 自身，不需要
org-transclusion 或 org-transclusion-blocks。

** TomoElpa（推荐）

[[https://blog.prayhand13013.top/tomoelpa/][TomoElpa]] 是本包的推荐安装方式。它同时提供
基于最新提交的 snapshots 和带版本号的 releases。归档路径没有可浏览的目录
索引；包列表请看上面的 TomoElpa 页面，下面的 URL 是 =package.el= 实际读取的
地址。把 snapshots 归档加入 =package-archives= 并刷新包索引，再用
=use-package= 安装和配置（Emacs 29 及更高版本自带 =use-package= 支持；Emacs
27–28 需要先从 GNU ELPA 安装）：

#+begin_src emacs-lisp
  (require 'package)
  (add-to-list 'package-archives
               '("tomoelpa-snapshots" .
                 "https://blog.prayhand13013.top/tomoelpa/snapshots/") t)
  (package-initialize)
  (package-refresh-contents)  ; 只需执行一次，或在归档更新后执行

  (require 'use-package)

  (use-package org-quote-link
    :ensure t
    :pin tomoelpa-snapshots
    :bind (("C-c q" . org-quote-link)
           :map org-mode-map
           ("C-c Q" . org-quote-link-refresh)))
#+end_src

如果希望使用带版本号的 releases 通道而不是 snapshots，把归档换成
=tomoelpa-releases= 并相应修改 =:pin= 的值：

#+begin_src emacs-lisp
  (add-to-list 'package-archives
               '("tomoelpa-releases" .
                 "https://blog.prayhand13013.top/tomoelpa/releases/") t)
  (package-refresh-contents)

  (use-package org-quote-link
    :ensure t
    :pin tomoelpa-releases
    :bind (("C-c q" . org-quote-link)
           :map org-mode-map
           ("C-c Q" . org-quote-link-refresh)))
#+end_src

不使用 =use-package= 时，执行一次
=M-x package-install RET org-quote-link RET= 即可安装。

** use-package 的 :vc 关键字

在 Emacs 30.1 及更高版本中，可以使用 =use-package= 的 =:vc= 关键字从
GitHub 直接下载本包，不需要 package archive：

#+begin_src emacs-lisp
  (use-package org-quote-link
    :vc (:url "https://github.com/TomoeMami/org-quote-link" :rev :newest)
    :bind (("C-c q" . org-quote-link)
           :map org-mode-map
           ("C-c Q" . org-quote-link-refresh)))
#+end_src

=:rev :newest= 会检出最新提交。如果不写 =:rev= 参数，那么 =:vc= 会尝试检出
最近一次 release；本仓库没有 release tag，因此请保留 =:rev :newest= 参数。
=:vc= 还需要 =git= 和网络连接。以后更新时执行
=M-x package-vc-upgrade RET org-quote-link RET= 即可。

更旧的 Emacs 版本请使用 TomoElpa 或 =straight.el= 安装。

** straight.el

#+begin_src emacs-lisp
  (straight-use-package
   '(org-quote-link :type git :host github :repo "TomoeMami/org-quote-link"))
#+end_src

配合 =use-package= 使用时：

#+begin_src emacs-lisp
  (use-package org-quote-link
    :straight (:type git :host github :repo "TomoeMami/org-quote-link")
    :bind (("C-c q" . org-quote-link)

** 手动安装

克隆仓库并把目录加入 =load-path= 即可：

#+begin_src emacs-lisp
  (add-to-list 'load-path "/path/to/org-quote-link")
  (require 'org-quote-link)
#+end_src

然后按需绑定按键：

#+begin_src emacs-lisp
  (define-key org-mode-map (kbd "C-c q") #'org-quote-link)
  (define-key org-mode-map (kbd "C-c Q") #'org-quote-link-refresh)
#+end_src

* 使用

** 推荐入口

只绑定 =org-quote-link= 一个命令即可。它会根据光标位置自动选择动作：

| 光标位置                                       | 动作               |
|------------------------------------------------+--------------------|
| 带有 =#+HEADER: :transclude [[LINK]]= 的块内部 | 刷新该块           |
| 单行 Org 链接上                                | 把链接转换成引用块 |
| 其它位置                                       | 报错，不修改 buffer |

分派时先判断块、再判断链接，因此块里的链接也会触发刷新。需要强制指定动作时，
仍可使用下面两个显式命令。

** 转换链接（显式命令）

光标放在链接上，执行 =org-quote-link-at-point= 命令。规则如下：

- 链接必须单独占一行，行首可以有空白；行内链接会报错，buffer 保持不变。
- 链接类型以 =org-store-link= 能生成的为准：支持 =file:= 链接（heading、
  CUSTOM_ID、target、命名元素、文字搜索、整个文件等）、 =id:= 链接，以及
  注册了 =:store= 的第三方类型（例如 denote）。
- heading 默认连标题行一起引用，可用 =org-quote-link-include-headline= 关闭；
  Org 来源会做逗号转义，避免 =*= 与 =#+= 开头的行破坏 quote-block。

完整的链接类型表与行为细节见 “更多文档” 中的技术细节。

** 刷新（显式命令）

引用块保存的是快照。把光标放在块里，执行 =org-quote-link-refresh= 命令即可
重新抓取内容；光标在 header、begin、正文、end 行都可以。它只依赖 Org 自身，
读取块里的 =#+HEADER: :transclude [[LINK]]= 行来定位链接。

在块里执行 =org-quote-link= 命令等同于刷新。

** 常用设置

| 变量                                   | 默认值  | 作用                   |
|----------------------------------------+---------+------------------------|
| =org-quote-link-block-type=            | "quote" | 生成的块类型           |
| =org-quote-link-include-headline=      | t       | heading 是否包含标题行 |
| =org-quote-link-escape-non-org-syntax= | nil     | 是否转义非 Org 内容    |
| =org-quote-link-link-handlers=         | denote  | 扩展链接类型的 alist   |

更多变量与扩展接口见 “更多文档” 中的技术细节。

* 与 org-transclusion-blocks 的差异对比

两者都使用 =#+HEADER: :transclude [[LINK]]= 加 quote-block 的形式，但定位不同：
org-quote-link 是零依赖的小工具，只负责把光标处的链接变成引用块并保存快照；
org-transclusion-blocks 是组件化 transclusion 框架，负责在自己的 header 语法下
抓取、刷新、调整范围并添加 overlay。

| 维度     | org-quote-link                          | org-transclusion-blocks                        |
|----------+-----------------------------------------+------------------------------------------------|
| 依赖     | 只依赖 Org（Emacs 27.1 与 Org 9.3）     | Emacs 29.1、Org 9.7、org-transclusion 1.4      |
| 定位     | 一条命令完成链接到引用块的转换          | 手写 header 与 block，再执行命令抓取           |
| 输入     | 光标处的 org-link                       | 已有的 header 与 block                         |
| 链接范围 | org-store-link 能生成的类型             | org-transclusion 的 fetcher 能处理的类型       |
| 内容粒度 | heading、元素、整个文件                 | 还可使用行号、thing-at-point、only-contents 等 |
| 块类型   | quote（可改为 example 或 verse）        | src、quote、example、special 等，src 走 Babel  |
| 刷新     | 自带的 org-quote-link-refresh           | org-transclusion-blocks-add 或菜单             |
| 转义     | Org 来源转义，非 Org 原样，可配置       | 由 org-transclusion-blocks 的选项控制          |
| 元数据   | 不添加，输出纯文本                      | 添加 text properties、overlay 等               |
| 自引用   | 拒绝 heading、元素、整个当前文件的嵌套  | 有自己的检查逻辑                               |

怎么选：

- 想要一条命令完成转换、保持零依赖、用自带命令刷新，请用 org-quote-link。
- 需要行号、thing-at-point、组件类型、菜单或 overlay，请用
  org-transclusion-blocks。
- 两者可以共存：org-quote-link 生成的格式与 blocks 的 header 约定相同，
  装了 blocks 时它的 add 命令通常也能识别。这是可选的互操作，不是
  org-quote-link 的依赖；差异与注意事项见 “更多文档” 中的技术细节。
